# 결 — 근정전 구조 탐험

Three.js r180 기반, 빌드가 필요 없는 정적 웹 프로토타입. 라이브러리는 dist/vendor에 포함되어 CDN 연결 없이 실행됩니다. 동기화된 sources 자료는 수정하지 않았습니다.

## 실행

프로젝트 폴더에서 `python3 -m http.server 4173 --directory dist`를 실행하고 http://localhost:4173 을 엽니다. ES modules를 사용하므로 index.html을 file://로 직접 열지 마세요.

## 조작

- 드래그: OrbitControls 회전 (모바일: 한 손가락)
- 뷰포트의 휠: 누적 입력량에 비례한 분해 0–100%. 휠 줌 비활성화.
- 슬라이더: 모바일·키보드 분해 (방향키, Home, End)
- 모델 클릭 또는 우측 레이어 버튼: 레이어 설명과 강조
- + / −: 확대·축소. 처음 시점: 카메라·선택·분해 초기화.

## 파일 구조

- dist/src/layers.js: 모델 소스 설정, 레이어 이름·해설·노드 매핑·분해 벡터
- dist/src/procedural.js: 교체 가능한 개념 근정전 모델 생성
- dist/src/model-loader.js: GLTFLoader와 절차형 모델을 공통 {root,layers,scale} 형태로 변환
- dist/src/main.js: 렌더러, 조명, 카메라, 입력, picking, 분해 보간
- dist/style.css: 데스크톱·모바일 UI

## 실제 GLB/GLTF로 교체

1. dist/models/geunjeongjeon.glb에 모델을 넣습니다. GLTF는 .bin/텍스처도 상대 경로를 유지합니다.
2. layers.js의 MODEL_CONFIG.kind를 'gltf'로, url을 해당 파일 경로로 바꿉니다.
3. LAYERS의 nodes를 모델에 있는 실제 Object3D 이름으로 매핑합니다. 각 레이어에 여러 이름을 지정할 수 있습니다. 권장 이름: Layer_Roof, Layer_Brackets, Layer_Frame, Layer_Walls, Layer_Base.
4. 매핑 노드는 고유 이름이며 서로 부모/자식 관계가 없어야 합니다. 공통 모델 루트 아래 형제 그룹으로 내보내는 방식을 권장합니다. 기본 자세가 y-up, +z 정면이어야 합니다. 리깅·스킨·내장 애니메이션은 이 정적 건축 파이프라인 범위 밖입니다.
5. 전체 폭을 normalizedWidth(기본 14)로 정규화하고 지면을 y=0에 맞춥니다. offset은 정규화된 공간의 [x,y,z]이므로 수직뿐 아니라 수평 분해도 설정할 수 있습니다.
6. 매핑된 노드를 새 레이어에 attach하여 월드 변환을 보존합니다. 매핑되지 않은 노드는 정적인 배경 구조로 남습니다. 누락·중복·중첩 매핑은 오류를 냅니다.
7. Draco / KTX2 압축 모델에는 별도로 DRACOLoader / KTX2Loader 설정과 디코더가 필요합니다. 기본 로더는 비압축 GLB/GLTF용입니다.

모델은 구조 설명용이며 실측 복원이 아닙니다. 중층 지붕 두 개는 지붕 레이어로 함께 움직이며, 실제 결구 순서를 시뮬레이션하지 않습니다.

## 2026-10-04 로딩·렌더링 최적화

기본 화면은 빠른 탐색용 LOD입니다. 레이어별 메시를 합친 후 Blender Decimate 0.12로 단순화해 1,717,775개 삼각형 / 121개 재질 묶음으로 줄였습니다. 기존 상세 모델은 14,319,769개 삼각형 / 3,461회 메시 드로입니다. 원본 다운로드 및 상세 모델의 메시 형상은 그대로 보관합니다.

기본 모델의 파일 합계는 25,951,608바이트(약 24.7MiB)이며, 기존 데스크톱 초기 모델 요청 파일 합계 232,702,498바이트 대비 약 89% 적습니다. 사이트 코드·디코더는 별도입니다. 총 배포 용량과 초기 전송량은 다릅니다. 정밀 자원은 버튼을 누르기 전에는 요청하지 않습니다.

빠른 탐색은 512px 색상 / 256px 표면 맵이며 단청 이미지 출처는 동일합니다. 정밀 보기는 기존 2048px 색상 맵을 WebP quality 92로 재압축했습니다. GPU 압축 텍스처는 아니며, 빠른 탐색의 해상도 감소와 텍스처 공유로 GPU 메모리 부담을 줄입니다. 기본 모델의 작은 장식·곡면은 단순화되어 있으므로 정밀 검토에는 정밀 보기를 선택해야 합니다.

빠른 모델은 텍스처를 내장한 단일 GLB에서 텍스처를 공유하고, 정밀 모델도 레이어 간 중복 텍스처 객체를 공유합니다. 모드 전환 시 이전 지오메트리·재질·텍스처와 ImageBitmap을 해제합니다. 모바일 렌더 해상도는 DPR 1로 제한하고 그림자 맵은 1024로 줄였습니다. 두 모드 모두 5개 분해 레이어, 선택 해설, 360도 회전, 핀치/Ctrl+휠 확대, 부드러운 시점 복귀를 유지합니다.

검증: 모든 glTF 참조 파일 존재, 게시 파일 크기 제한, JavaScript 구문, 실제 브라우저 빠른→정밀→빠른 전환, 레이어 분해 및 콘솔 오류 확인. 로컬 최초 모델 준비는 약 1.3초였으나 네트워크·기기별 운영 로딩 시간이나 FPS를 보장하지 않습니다. 변환 기록은 dist/models/provenance.json에 있습니다.

## 2026-10-04 사전 로딩 + 자동 LOD로 변경

위의 수동 품질 전환 방식은 폐기했습니다. 시작 시 저·고상세 모델을 모두 다운로드/디코딩하고, 텍스처 GPU 업로드, shader compileAsync 및 작은 오프스크린 렌더로 모든 형상 버퍼를 준비한 뒤 로딩 화면을 닫습니다. 로딩 중 조작은 차단합니다. 초기 대기 시간과 상주 메모리는 늘어나지만 이후 LOD 전환에서는 다운로드나 모델 파싱을 하지 않습니다.

자동 LOD는 5개 건축 레이어별로 계산합니다. 카메라에서 레이어 월드 경계 상자까지의 거리가 정규화 단위 6 미만이면 정밀 형상, 8 이상이면 경량 형상으로 전환합니다. 중간 구간은 기존 상태를 유지해 반복 전환을 막습니다. 구조 분해로 이동한 위치도 거리 계산에 반영합니다. 두 표현에 동일한 좌표 정규화를 적용하고 선택 판정은 현재 보이는 표현만 사용합니다.

이는 개별 부재마다 전환하는 세밀한 LOD가 아닌 레이어 단위의 2단계 구현입니다. 가까이서 여러 레이어가 모두 정밀해지면 처리량이 다시 증가하므로 모든 기기에서 끊김 없는 FPS를 보장하지 않습니다. 애니메이션/회전/핀치/Ctrl+휠/해설은 유지합니다.

브라우저 검증: 사전 준비 완료 후 GPU geometry 2,617개 / texture 658개가 상주하며, 확대·축소에 따라 정밀 레이어 0→5→1→0 전환을 확인했습니다. 로컬 준비는 약 12초였고 네트워크/기기마다 달라집니다. 원거리 본체는 1,717,775 triangles, 근거리는 화면에 보이는 정밀 레이어에 따라 달라집니다. 수동 전환 버튼은 제거했습니다.

## 2026-10-04 GPU 압축 텍스처 시험 적용

KTX2 / KHR_texture_basisu로 654개 이미지를 변환했습니다. 기존 웹 버전의 모든 텍스처 해상도와 저·고상세 Draco 형상 바이트는 그대로입니다. 사전 로딩, LOD 거리 6/8, 카메라 조작은 변경하지 않았고 인스턴싱은 적용하지 않았습니다.

색상/ORM은 ETC1S quality 255, compression level 2입니다. 노멀은 UASTC quality 3 + Zstd 18이며 노멀 채널 배치는 그대로 유지했습니다. 샘플 중 오차가 상대적으로 컸던 t_gjj_2f_rafter01_bc는 UASTC quality 3 + RDO lambda 0.5로 올렸습니다. 색상은 sRGB, 표면 맵은 linear로 지정하고 mipmap을 포함합니다. KTX-Software 4.4.2로 인코딩했고 Three.js r180 KTX2Loader 및 Basis transcoder를 사용합니다.

검증 브라우저에서는 모든 텍스처가 BC7 또는 ASTC 4x4로 올라갔고 실제 transcoded mip payload 합계는 736,642,160 bytes(약 0.69GiB)였습니다. 이전 RGBA8+mipmap 추정치 약 2.72GiB 대비 약 75% 적지만, 이는 전체 GPU 메모리 측정이 아니며 기기/지원 압축 형식에 따라 달라집니다. 압축을 지원하지 않는 장치에서는 비압축 fallback으로 절감 효과가 제한될 수 있습니다. 네트워크 파일 크기는 GPU 메모리 크기와 다르며 이번 고품질 설정으로 일부 파일은 WebP보다 커졌습니다.

단청 샘플 RGB8 복원 비교 PSNR은 약 30.6~40.6dB, 노멀 샘플은 약 56.6dB입니다. 손실 압축이며 동등 품질을 보장하지 않습니다. 사용자 확대 화면 검토 후 다음 작업 여부를 결정합니다. 유휴 상태 후 끊김의 해결 여부는 아직 장시간 비교 측정하지 않았습니다. 출처 및 상세 변환 사양은 models/provenance.json에 있습니다.

게시 파일은 동일한 Three.js r180 공식 minified 빌드를 사용하여 모델 품질 변경 없이 패키지 크기를 줄였습니다.

## 반복 부재 인스턴싱
